## 1. 功能概述

改造后：

- 独立的 `/music/` 页面默认关闭，不再出现在导航栏「记录」下拉中。
- 影视与游戏页面（`/movies-games/`）新增一个 **「音乐」Tab**，用于展示专辑、EP、单曲收藏。
- 音乐条目与影视、游戏条目共享同一个 `bangumi` 内容集合，通过 `category: music` 区分。
- 新增 `musicType` 字段，可标记条目为 `album`（专辑）、`ep`（EP）或 `single`（单曲）。
- 音乐播放继续使用全局唯一的 `MusicManager` 音频管理器，点击卡片即可播放。

## 2. 开启与关闭

### 2.1 关闭独立音乐页面

编辑 `src/config/siteConfig.ts`：

```ts
pages: {
  // ...
  musicPage: false,  // 关闭独立的 /music/ 页面
}
```

关闭后：

- `/music/` 路由会返回 404 重定向。
- 导航栏「记录」下拉中的「音乐」入口自动隐藏（由 `navBarConfig.ts` 根据 `siteConfig.pages.musicPage` 动态生成）。

### 2.2 音乐分区是否显示

`/movies-games/` 页面的「音乐」Tab 是**按需显示**的：

- 当 `bangumi` 集合中存在 `category: music` 的条目时，才会显示「音乐」Tab。
- 若没有任何音乐条目，Tab 自动隐藏，不影响影视与游戏原有功能。

## 3. 添加音乐数据

在 `src/content/bangumi/music/` 目录下创建 Markdown 文件：

```markdown
---
title: "专辑或单曲名称"
artist: "艺术家名"
category: music
musicType: album          # album | single | ep，可选
image: /assets/music/covers/cover.jpg
score: 9
status: 2                 # 1=想听 2=听过 3=在听 4=搁置 5=抛弃
comment: "简短评论，可选"
published: 2024-01-15
audioUrl: /assets/music/songs/song.mp3    # 本地音频或直链
lrcUrl: /assets/music/lyrics/song.lrc     # 歌词文件，可选
---

可选的额外介绍文字。
```

> 音乐条目的存放目录名不一定是 `music/`，只要 frontmatter 中 `category: music` 即可被识别。

### 3.1 批量示例

```markdown
---
title: "范特西"
artist: "周杰伦"
category: music
musicType: album
image: /assets/music/covers/fantasy.jpg
score: 10
status: 2
comment: "华语经典"
published: 2001-09-14
---
```

```markdown
---
title: "晴天"
artist: "周杰伦"
category: music
musicType: single
image: /assets/music/covers/sunny.jpg
score: 9
status: 2
comment: "单曲循环"
published: 2003-07-16
audioUrl: /assets/music/songs/sunny.mp3
lrcUrl: /assets/music/lyrics/sunny.lrc
---
```

## 4. 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 专辑/单曲名称 |
| `artist` | 否 | 艺术家名，显示在卡片上 |
| `category` | 是 | 固定为 `music` |
| `musicType` | 否 | `album`、`single`、`ep`，不填则不显示类型标签 |
| `image` | 是 | 封面图片路径 |
| `score` | 否 | 评分（0-10），大于 0 时显示星级 |
| `status` | 是 | 收藏状态：`1`想听、`2`听过、`3`在听、`4`搁置、`5`抛弃 |
| `comment` | 否 | 简短评论，悬停时显示（仅无音频时）或作为备注 |
| `published` | 否 | 发行/收藏日期，影响排序 |
| `audioUrl` | 否 | 音频直链，有值时卡片显示播放按钮 |
| `lrcUrl` | 否 | 歌词文件链接 |
| `metingServer` | 否 | Meting 平台：`netease`、`tencent` 等 |
| `metingId` | 否 | Meting 歌曲/专辑/歌单 ID，可与 `audioUrl` 二选一 |

## 5. 播放方式

### 5.1 本地音频直链

配置 `audioUrl` 即可：

```yaml
audioUrl: /assets/music/songs/歌曲名.mp3
```

音频文件应放在 `public/assets/music/songs/` 目录下。

### 5.2 通过 Meting API 播放

如果已有网易云/QQ音乐等平台的资源，可配置 `metingServer` + `metingId`：

```yaml
metingServer: netease
metingId: "123456789"
```

页面加载时会通过 `musicPlayerConfig.meting.api` 自动解析出真实音频 URL。

> Meting API 地址在 `src/config/musicConfig.ts` 的 `meting.api` 中配置，默认使用 `https://api.i-meto.com/meting/api`。

### 5.3 播放行为

- 点击带播放按钮的卡片，会调用全局 `MusicManager` 的 `setPlaylist()` 方法。
- 当前播放的卡片会高亮显示，并展示音波动画。
- 全站仍然只有 `MusicManager.astro` 中那一个 `<audio>` 元素，不会创建新的音频实例。
- 如果音乐条目没有配置 `audioUrl` 或 `metingId`，卡片只展示收藏信息，不显示播放按钮。

## 6. 样式与显示

### 6.1 卡片信息

每张音乐卡片展示：

- 封面图
- 状态标签（想听/听过/在听/搁置/抛弃）
- 类型标签（专辑/单曲/EP）
- 评分（若大于 0）
- 标题与艺术家
- 播放按钮（仅可播放条目）
- 悬停评论（无音频时）

### 6.2 筛选

音乐 Tab 支持与其他 Tab 相同的状态筛选器：全部 / 听过 / 在看 / 想看 / 搁置 / 抛弃。音乐条目在筛选时使用音乐专属的状态文案（想听/听过/在听/搁置/抛弃）。

### 6.3 分页

音乐分区使用与其他分区一致的 `ClientPagination` 客户端分页，默认每页 12 条（移动端 6 条）。

## 7. 常见问题

### Q1: 为什么添加了音乐文件，但「音乐」Tab 没有显示？

- 检查 frontmatter 中是否写了 `category: music`。
- 检查 `musicPlayerConfig.meting.api` 配置是否可用（仅影响播放，不影响显示）。
- 检查文件是否在 `src/content/bangumi/` 目录下（子目录不限）。

### Q2: 点击播放没有反应？

- 打开浏览器控制台，查看是否有 `Music manager not found` 报错。如果有，说明全局 `MusicManager` 未初始化，检查 `sidebarConfig.ts` 中是否完全禁用了音乐播放器组件。
- 检查 `audioUrl` 是否可访问，或 `metingServer` + `metingId` 是否能解析出真实 URL。
- 跨域音频资源可能无法播放，建议放在 `public/` 下或使用支持 CORS 的 CDN。

### Q3: 想重新开启独立 `/music/` 页面怎么办？

1. 将 `src/config/siteConfig.ts` 中 `musicPage` 改回 `true`。
2. 导航栏会自动恢复「音乐」入口。
3. `/music/` 页面会恢复为原来的 3D 可视化播放器。

> 注意：独立音乐页面现在使用 `MusicManager.setPlaylist()` 加载收藏列表，不再依赖已不存在的 `loadExternalPlaylist` 方法。

### Q4: 类型标签为什么显示英文？

检查 `musicType` 值是否为 `album`、`single`、`ep` 之一，其他值不会被识别。
