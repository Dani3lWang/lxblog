## 1. 视觉风格调整

### 1.1 核心文件

| 文件 | 作用 |
|------|------|
| `src/styles/variables.styl` | 主题色、颜色变量、圆角、阴影、模糊等 CSS 变量 |
| `src/styles/navbar.css` | 导航栏样式 |
| `src/styles/main.css` | 主样式入口，包含底部渐变高光、下拉面板等 |
| `src/config/siteConfig.ts` | 站点配置（主题色相、卡片样式等） |

### 1.2 当前风格

lxblog 保留了 Firefly 主题的 **翠绿色 (hue: 165)** 色彩体系，仅将以下效果置零以实现极简/粗野主义风格：

- **圆角**：全部置零（保留 `--radius-full: 9999px` 用于圆形元素）
- **阴影**：全部移除（`box-shadow: none`）
- **模糊**：全部移除（`backdrop-filter` 置零）
- **导航栏**：纯色背景，滚动时隐藏，超过阈值后收缩为 pill 带 2px 边框

### 1.3 恢复圆角/阴影/模糊

如果希望恢复原版 Firefly 的圆润风格，编辑 `src/styles/variables.styl`，将以下变量恢复：

```stylus
/* —— 圆角恢复 —— */
--radius-large: 1rem
--radius-sm: 0.25rem
--radius-md: 0.375rem
--radius-lg: 0.5rem
--radius-xl: 0.75rem
--radius-2xl: 1rem
--radius-3xl: 1.5rem

/* —— 阴影恢复 —— */
--shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.05)
--shadow-md: 0 4px 6px rgba(0, 0, 0, 0.1)
--shadow-lg: 0 10px 15px rgba(0, 0, 0, 0.1)
--shadow-xl: 0 20px 25px rgba(0, 0, 0, 0.1)
--shadow-2xl: 0 25px 50px rgba(0, 0, 0, 0.25)
--shadow-navbar: 0 4px 16px rgba(0, 0, 0, 0.1)
--shadow-navbar-dark: 0 4px 16px rgba(0, 0, 0, 0.2)
--shadow-button: 0 4px 12px rgba(0, 0, 0, 0.15)
--shadow-button-dark: 0 4px 12px rgba(255, 255, 255, 0.1)

/* —— 模糊恢复 —— */
--blur-sm: 4px
--blur-md: 8px
--blur-lg: 12px
--blur-xl: 16px
--blur-2xl: 20px
--blur-3xl: 24px
```

同时需要恢复 `main.css` 中的 `shadow-xs` 引用（在 enable-card-border 相关规则中）以及 `navbar.css` 中的毛玻璃效果。

如果同时要恢复导航栏的毛玻璃和圆角，需要还原 `src/styles/navbar.css` 中被移除的 Banner 模式相关样式（可参考原 Firefly 模板）。

### 1.4 切换为黑白极简配色

`variables.styl` 文件末尾已注释了完整的**黑白极简配色方案**（chroma = 0）。如需切换：

1. 编辑 `src/styles/variables.styl`，找到文件末尾的注释块
2. **取消注释** `/* ===== 黑白极简亮色方案 ===== */` 和 `/* ===== 黑白极简暗色方案 ===== */` 两个注释块
3. **注释掉** 上方正在使用的原有颜色变量（亮色 `:root` 和暗色 `:root.dark` 块）
4. 同时在 `src/config/siteConfig.ts` 中将 `hue` 改为 `230`
5. 保存后重启开发服务器即可生效

### 1.5 修改主题色相

编辑 `src/config/siteConfig.ts`：

```typescript
themeColor: {
    hue: 165,  // 改为你想要的值：0=红, 120=绿, 200=青, 230=蓝紫, 280=紫, 345=粉
    fixed: false,  // true=隐藏访客的色相选择器
    defaultMode: "system",  // light | dark | system
},
```

### 1.6 导航栏特殊效果调整

导航栏当前行为：
- **滚动超过 50px** → 添加 `scrolled` 类 → 收缩为居中 pill，带 2px 边框
- **向下滚动** → 添加 `nav-hidden` 类 → 隐藏（`translateY(-100%)`）
- **向上滚动** → 移除 `nav-hidden` → 显示

如需调整滚动阈值，编辑 `src/components/layout/Navbar.astro` 第 327 行的 `threshold` 值。

如需修改 pill 样式，编辑 `src/styles/navbar.css` 中 `#navbar.scrolled>div` 的规则。

## 2. 记录功能模块

### 2.1 模块概览

| 模块 | 路由 | 数据源 | 开关配置 |
|------|------|--------|---------|
| 书架 | `/books/` | `src/content/bangumi/` (category=book) | `siteConfig.pages.books` |
| 影视与游戏 | `/movies-games/` | `src/content/bangumi/` (anime/game/real/music) | `siteConfig.pages.moviesGames` |
| 音乐 | `/music/`（默认关闭） | `src/content/bangumi/` (category=music) | `siteConfig.pages.musicPage` |
| 更新日志 | `/changelog/` | `src/content/changelog/` | `siteConfig.pages.changelog` |
| 规划 | `/routines/` | `src/content/routines/` | `siteConfig.pages.routines` |
| 足迹 | `/places/` | `src/content/places/` | `siteConfig.pages.places` |

### 2.2 启用/禁用页面

所有记录功能页面默认**禁用**（开关为 `false`）。要启用，编辑 `src/config/siteConfig.ts`：

```typescript
pages: {
    // ... 其他开关 ...
    books: true,        // 启用书架
    moviesGames: true,  // 启用影视与游戏
    musicPage: true,    // 启用音乐页面
    changelog: true,    // 启用更新日志
},
```

**注意**：启用开关后，导航栏的"记录"下拉菜单会自动显示对应子项。如果启用但页面路径不存在，访问时会跳转到 404。

### 2.3 添加书架数据

在 `src/content/bangumi/book/` 目录下创建 `.md` 文件：

```markdown
---
title: 书籍名称
category: book
status: 2          # 1=想读, 2=读过, 3=在读, 4=搁置, 5=抛弃
score: 8           # 评分 (0-10)
image: https://example.com/cover.jpg
published: 2026-01-01
tags: [分类1, 分类2]
---

书籍简介（可选，支持 Markdown）
```

### 2.4 添加影视与游戏数据

在 `src/content/bangumi/anime/`、`src/content/bangumi/game/` 或 `src/content/bangumi/real/` 下创建 `.md` 文件：

```markdown
---
title: 作品名称
category: anime        # anime | game | real
subcategory: movie     # movie | tv | anime | documentary（可选）
status: 2              # 1=想看, 2=看过, 3=在看, 4=搁置, 5=抛弃
score: 9
image: https://example.com/poster.jpg
published: 2026-01-15
tags: [标签1, 标签2]
---
```

### 2.5 添加音乐数据

音乐收藏现在默认并入 `/movies-games/` 页面的「音乐」Tab，不再使用独立的 `/music/` 页面。

在 `src/content/bangumi/music/` 下创建 `.md` 文件：

```markdown
---
title: 专辑或单曲名称
category: music
musicType: album          # album | single | ep，可选
artist: 歌手名
status: 2                 # 1=想听, 2=听过, 3=在听, 4=搁置, 5=抛弃
score: 8
image: https://example.com/cover.jpg
published: 2026-02-01
audioUrl: /assets/music/songs/歌曲文件.mp3    # 可选
lrcUrl: /assets/music/lyrics/歌词文件.lrc     # 可选
metingServer: netease     # 可选，配合 metingId 使用
metingId: "123456789"     # 可选，Meting 平台资源 ID
---
```

只要存在 `category: music` 的条目，`/movies-games/` 页面就会自动出现「音乐」Tab。详情见 [影视与游戏音乐分区使用指南](./影视与游戏音乐分区使用指南.md)。

### 2.6 添加更新日志

在 `src/content/changelog/` 下创建 `.md` 文件：

```markdown
---
version: v1.1
date: 2026-07-15
type: feature         # feature | improvement | fix | removal
description: 新增了某某功能
---

详细说明（可选，支持 Markdown）
```

### 2.7 添加规划

在 `src/content/life/routines/` 下创建 `.md` 文件：

```markdown
---
name: 每日学习计划
time: 全天
icon: 📚
description: 日常工作学习安排
updatedAt: 2026-07-01
---

| 时间段 | 安排 |
|--------|------|
| 8:00 | 起床 |
| 9:00-12:00 | 工作学习 |
```

### 2.8 添加足迹

在 `src/content/life/places/` 下创建 `.md` 文件：

```markdown
---
date: 2026-07-01
province: 北京
city: 北京
experience: 去故宫游玩了一整天
visitCount: 2
lat: 39.9042     # 可选（纬度，用于地图标注）
lng: 116.4074    # 可选（经度，用于地图标注）
---
```

**注意**：足迹页面使用 ECharts 中国地图，需要网络加载地图数据。如果无法显示地图，可能是 CDN 被墙，可配置本地 `china.json` 文件。

## 3. 导航栏配置

### 3.1 配置文件

`src/config/navBarConfig.ts` — 导航栏链接和菜单结构。

### 3.2 添加/修改导航栏链接

在 `LinkPresets` 对象中添加预设，然后在 `getDynamicNavBarConfig()` 函数中引用：

```typescript
// 添加预设
export const LinkPresets: Record<string, NavBarLink> = {
    // ... 已有预设 ...
    MyNewPage: {
        name: "新页面",
        url: "/new-page/",
        icon: "material-symbols:star",
    },
};
```

在 `getDynamicNavBarConfig()` 中使用：

```typescript
links.push(LinkPresets.MyNewPage);  // 直链
// 或作为子菜单
links.push({
    name: "父菜单",
    url: "#",
    icon: "material-symbols:folder",
    children: [
        LinkPresets.MyNewPage,
        // ... 更多子项
    ],
});
```

### 3.3 记录菜单的动态控制

"记录"下拉菜单中的书架、影视与游戏、音乐、更新日志、规划、足迹 6 项，会根据 `siteConfig.pages` 的开关值在构建时动态显示。如果开关关闭，对应的子项不会出现在导航栏中。

## 4. 国际化翻译

### 4.1 相关文件

| 文件 | 语言 |
|------|------|
| `src/i18n/i18nKey.ts` | 翻译键枚举定义 |
| `src/i18n/languages/zh_CN.ts` | 简体中文 |
| `src/i18n/languages/en.ts` | 英文 |
| `src/i18n/languages/ja.ts` | 日文 |
| `src/i18n/languages/ru.ts` | 俄文 |
| `src/i18n/languages/zh_TW.ts` | 繁体中文 |
| `src/i18n/translation.ts` | 翻译函数 |

### 4.2 添加新翻译

1. 在 `src/i18n/i18nKey.ts` 的枚举中添加新键：
   ```typescript
   myNewKey = "myNewKey",
   ```

2. 在每个语言文件中添加对应的翻译值：
   ```typescript
   [Key.myNewKey]: "我的新翻译",
   ```

3. 在组件中使用：
   ```astro
   import I18nKey from "@/i18n/i18nKey";
   import { i18n } from "@/i18n/translation";
   
   <span>{i18n(I18nKey.myNewKey)}</span>
   ```

## 5. 音乐下载脚本

### 5.1 脚本位置

`scripts/fetch-music/` 目录包含完整的音乐下载工具链。

### 5.2 安装依赖

```bash
pip install mutagen
```

### 5.3 搜索并下载单曲

```bash
cd scripts/fetch-music
python fetch-lrc.py "晴天" "周杰伦" --md --server=netease
```

参数说明：
- `--md`：同时生成博客用的 `.md` 数据文件
- `--server=netease`：指定平台（netease/tencent/kugou/xiami/baidu）
- `--out=路径`：指定下载输出目录
- `--test`：诊断模式（测试各平台可用性）

### 5.4 批量下载

1. 编辑 `playlist.txt`，格式为：
   ```
   歌曲名：晴天，歌手名：周杰伦
   歌曲名：十年，歌手名：陈奕迅
   ```

2. 运行批量下载：
   ```bash
   python batch-download.py playlist.txt --server=netease
   ```

### 5.5 获取歌词（仅处理本地文件）

```bash
python fetch-lrc.py ./downloads/歌曲文件.m4a
```

### 5.6 输出目录

- 音频文件：`public/assets/music/songs/`
- 封面图片：`public/assets/music/covers/`
- 歌词文件：`public/assets/music/lyrics/`

下载完成后，需将歌曲信息添加到 `src/config/musicConfig.ts` 的 `local.playlist[]` 中才能在播放器中播放。

### 5.7 配置 Meting API

编辑 `scripts/fetch-music/fetch-lrc.py` 第 59-62 行的 `API_ENDPOINTS` 列表：

```python
API_ENDPOINTS = [
    "https://mu.tsh520.cn/api",                  # 你的自部署实例（推荐）
    "https://api.i-meto.com/meting/api",           # 官方实例
    "https://api.injahow.cn/meting/",              # 备用
]
```

## 6. 内容集合 (Content Collections)

### 6.1 集合定义文件

`src/content.config.ts` 定义了所有 Content Collections。当前激活的集合：

| 集合名 | 数据目录 | 用途 |
|--------|---------|------|
| `posts` | `src/content/posts/` | 博客文章 |
| `spec` | `src/content/spec/` | 特殊页面（关于、友链等） |
| `bangumi` | `src/content/bangumi/` | 书架、影视与游戏、音乐数据 |
| `changelog` | `src/content/changelog/` | 更新日志 |
| `life` | `src/content/life/` | 足迹、笔记本等生活记录 |
| `routines` | `src/content/life/routines/` | 规划数据 |

### 6.2 数据类型

**bangumi 集合**支持 5 种类型，通过 `category` 字段区分：

| 类型 | 页面 | 筛选条件 |
|------|------|---------|
| `book` | 书架 | `category === "book"` |
| `anime` | 影视与游戏 | `category === "anime"` |
| `game` | 影视与游戏 | `category === "game"` |
| `real` | 影视与游戏 | `category === "real"` |
| `music` | 音乐 | `category === "music"` |

### 6.3 添加新集合

如果需要添加新的内容集合，在 `src/content.config.ts` 中：

```typescript
const myCollection = defineCollection({
    loader: glob({ pattern: "**/*.{md,mdx}", base: "./src/content/my" }),
    schema: z.object({
        title: z.string(),
        // ... 字段定义
    }),
});

export const collections = {
    posts: postsCollection,
    spec: specCollection,
    // ... 其他集合
    my: myCollection,  // 添加新集合
};
```

## 7. 常见问题

### Q1: 启用记录页面后访问返回 404

确认页面对应的开关在 `siteConfig.ts` 中已设为 `true`。如果开关已打开但仍 404，可能是页面文件缺少了页面开关检查后的 `Astro.redirect("/404/")` 逻辑，检查对应页面文件的 frontmatter 顶部。

### Q2: 音乐页面 3D 可视化器不工作

确认已安装 `three` 依赖：
```bash
pnpm add three
```

如仍有问题，检查 `src/components/features/music-visualizer/` 中的 Svelte 组件是否正确导入。

### Q3: 足迹地图不显示

足迹页面通过 CDN 加载 ECharts 和 China 地图数据。如果网络被墙，可在 `public/` 下放置本地 `china.json` 地图文件，并修改 `src/pages/life/places.astro` 中的加载逻辑。

### Q4: 构建时提示 "The collection 'posts' does not exist"

这是因为 `src/content/posts/` 目录不存在。运行以下命令创建：
```bash
mkdir -p src/content/posts
```
或者临时添加一个占位文件。

### Q5: 编译 `three` 时遇到 `resolve` 错误

```bash
pnpm add three
pnpm add -D @types/three
```

### Q6: 修改 CSS 后不生效

Stylus 和 Tailwind CSS 变量的修改需要重启开发服务器：
```bash
pnpm dev
```
重新启动后再刷新页面。
