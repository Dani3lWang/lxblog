## 目标
GitHub Actions 每天北京时间 08:00（UTC 0:00）自动执行上游同步：fetch upstream → master 快进 → push origin/master。

## 方案（用户已确认：GitHub Actions 定时，每天 08:00）

### 1. 修改 `.github/workflows/sync-upstream.yml`（kelly 上提交）
现有文件已有完整逻辑（分叉检查、ff-only、Summary、手动触发），只缺两处：

- **恢复 schedule**：
  ```yaml
  on:
    schedule:
      - cron: '0 0 * * *'   # 每天 08:00 北京时间（UTC+8）
    workflow_dispatch:
  ```
- **修复 upstream remote**（当前缺失，Actions 环境里 `git fetch upstream` 必失败）：
  ```yaml
  - name: Add upstream remote
    run: git remote add upstream https://github.com/CuteLeaf/Firefly.git
  ```
  放在 "Fetch upstream" 步骤之前。

- 保留：分叉保护（diverged 时报错不推送）、ff-only 快进、`workflow_dispatch` 手动触发、Summary 输出。

### 2. 分支处理（让 schedule 生效）
GitHub 的 schedule/workflow_dispatch 读取**默认分支**上的工作流定义：
- 先用 `gh repo view Dani3lWang/lxblog --json defaultBranchRef` 确认默认分支
- 若默认分支是 **kelly**：直接推 kelly 即可
- 若默认分支是 **master**：master 是纯净镜像（只接受上游 ff），不能直接提交——需要 `gh repo edit --default-branch kelly` 把默认分支切到 kelly（kelly 本就是主分支），或与用户确认后另行处理

### 3. 提交与推送
- 按 AGENTS.md 约定立即提交（`chore(ci): 恢复上游同步定时任务并修复 upstream remote 配置`）
- push 到对应分支

### 4. 验证
- `gh workflow run sync-upstream.yml` 手动触发一次，确认流程跑通（当前上游无新提交时输出 ahead_or_equal=true 跳过推送）
- 检查 Actions run 日志成功
- （可选）本地 `pnpm sync` 语义不变，不受影响

## 不包含（已与用户确认的方案边界）
- **kelly 的 rebase 不做自动定时**：小步同步后冲突少，rerere 自动解决大部分；需要时手动 `pnpm sync:full:local`（或由我按需执行）。若未来希望 kelly 也全自动，可再评估 ZCode 定时任务。
- 不改动本地 sync 脚本（`sync-upstream.sh` 祖先判断 bug 已在本次会话修复）

## 风险
- Actions cron 有最小间隔限制（5 分钟），每天一次无问题；schedule 可能因仓库不活跃延迟执行（GitHub 限制），但手动触发入口始终可用
- master 若与上游意外分叉，工作流会报错停止（安全保护），不会强推
